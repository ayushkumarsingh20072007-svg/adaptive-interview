Section 01

Project Overview & Architecture

InterviewIQ is a production-grade, full-stack AI interview simulation platform built with Next.js 16 and powered by Google Gemini 3.8 Flash. It provides a complete end-to-end technical interview experience: resume upload → adaptive AI question generation → real-time answer evaluation → integrity monitoring → AI-generated scorecards with evidence citations.

The platform serves two user types: Candidates (take AI-driven technical interviews) and Recruiters (review all candidate performance, manage shortlist pipeline, access analytics). Both use a unified dashboard with role-specific tab sets.

🔑 Core Philosophy — Three Pillars:
• Adaptive Intelligence — Questions change dynamically based on answer quality and keyword detection
• Evidence-Based Evaluation — Every skill score backed by verbatim quotes from the candidate's own answers
• Integrity Assurance — Server-enforced proctoring: 1st violation = warning, 2nd = automatic termination

User Roles & Authentication

🎓

Takes AI-driven technical interviews, uploads resume, views personal scorecard & history, uses AI practice assistant. Pages: Setup, Interview Workspace, Report, Dashboard (Overview, History, Skills, Practice, Settings).

💼

Recruiter

Views ALL candidate evaluation reports, manages shortlist pipeline, submits notes, accesses platform-wide analytics. Pages: Dashboard (Pipeline, Analytics, Reviews). Cannot take interviews themselves.

Authentication System (Custom-Built)

Zero third-party auth libraries. Built entirely on Node.js built-in crypto module.

  • Password Hashing: PBKDF2 with SHA-512, 100,000 iterations, 64-byte output, unique 16-byte random salt per user (prevents rainbow table attacks)
  • Timing-Safe Comparison: crypto.timingSafeEqual() prevents timing-attack exploitation during login verification
  • Session Tokens: 32-byte cryptographically random hex tokens stored as interviewiq_session HTTP-only cookie (JavaScript cannot access it)
  • Session Expiry: 7-day rolling sessions stored in the AuthSession DB table — expired sessions auto-rejected
  • API Security: Every route calls resolveRequestUser(req) — client-supplied user IDs in JSON bodies are NEVER trusted
  • Demo Login: /api/auth/demo-login — 1-click login for demo accounts without exposing passwords in URLs or query params

Demo Accounts (Built-in, Pre-Seeded)

Seeded via prisma/seed.ts. All use password Password123. Available as 1-click buttons on the login page.

3.3 Adaptive AI Question Engine

LayerWhen UsedHow It Works
Gemini AI (Primary)Valid API key + network reachableStructured prompt containing: role, level, focus, resume excerpt, previously asked questions (dedup prevention), answer history. Returns JSON question object. Primary model: gemini-3.8-flash, fallback: gemini-3.7-flash.
Static Question BankGemini timeout or rate-limitCurated per-role question bank (in mock-data.ts) with follow-up branching trees. Selects only questions not already asked in current session.
Adaptive BranchingAfter every answer submissionIf specific trigger keywords appear in the answer (e.g. "distributed lock" triggers a fencing tokens question), the engine selects the pre-defined follow-up to probe deeper into that area.

⏱️ Timeout & Retry Logic: 6.5-second timeout per Gemini call. If primary model fails → 1.5s delay → retry with fallback model. If both fail → static question bank used. Interview never stalls or hangs.

3.4 Answer Evaluation System

Every submitted answer is evaluated server-side via Gemini's evaluate-answer API, returning a structured AnswerFeedback object:

💯

Score (0–100)

Holistic: technical accuracy, keyword coverage, depth, clarity, reasoning quality — combined into a single score.

✅

Strengths Identified

Specific concepts the candidate demonstrated correctly, with supporting evidence from their answer text.

❌

Knowledge Gaps

Missing concepts, incorrect assumptions, or incomplete explanations — flagged with technical specificity.

📝

Adaptive Note

AI explanation of how the next question's difficulty will be calibrated based on this performance — gives candidates visibility into the scoring logic.

🔬

Technical Labels

Technical Correctness: accurate / partial / incorrect
Explanation Quality: clear / acceptable / confusing
Completeness: complete / partially_complete / incomplete

💬

Verbatim Evidence Quote

An exact substring extracted from the candidate's answer. Used as proof in the report's evidence citations. Prevents AI hallucination of skills not actually demonstrated.

Evasive Answer Detection: Deterministic fallback catches non-answers. Phrases like “I don't know”, “skip”, “idk”, “test”, “asdf” or answers under 15 characters are scored 10–25 max, with gaps auto-populated from expected keywords.

3.5 Interview Integrity & Proctoring System

👁️

Tab/Window Focus Monitoring

JavaScript visibilitychange + blur events detect tab switching, window minimization, or navigating away during the interview.

⚠️

1st Violation → Warning

Server records warning event in DB. A modal appears notifying the candidate a violation was recorded. Interview continues normally.

🚫

2nd Violation → Termination

Interview auto-terminates. Session status set to terminated_integrity in DB. No further answers accepted. Report verdict changed to “Terminated (Integrity Policy)”.

🔐

Policy Acknowledgment

Candidates must click “I Acknowledge” before seeing any question. Timestamp + policy version (v1.0) stored server-side.

🔒

Server-Side Enforcement

Violation counts maintained server-side only. Client-supplied violationCount, actionTaken, status in API requests are explicitly rejected.

🎯

Idempotency Guard

Each event has a unique idempotency key. Network retry storms cannot cause the same violation to be counted twice. Duplicate keys are silently deduplicated.

⚠️ Report Impact: Terminated sessions show: verdict = “Terminated (Integrity Policy)”, full audit trail (event timestamps, question active at violation, policy version). Recruiters see integrity status prominently in the pipeline view.

3.6 Evaluation Report & Scorecard (/report/[sessionId])

AI-generated after interview completion. Persisted to the DB immediately. Serves as the definitive, shareable performance record.

🏆

Overall Score & Verdict

0–100 composite + one of four verdicts: Strong Hire Recommendation, Hire Recommendation, Additional Review Recommended, Terminated (Integrity Policy).

📊

Skill Competency Metrics

Each skill area scored independently: Needs Focus → Developing → Proficient → Mastery. Includes evidence quote, rubric criteria, confidence rating per skill.

🔍

Skill Status Classification

Demonstrated (score ≥75 + verbatim evidence), Claimed Unvalidated (mentioned but not proven with evidence), Not Assessed (not tested during session).

💬

Evidence Citations

Verbatim quotes from candidate answers mapped to specific competencies, with high/medium/low confidence ratings and question index references.

📋

Full Answer Transcript

Every Q&A pair shown with individual scores, strengths, gaps, submission timestamps, category & difficulty labels. Expandable/collapsible per-question.

🗺️

Actionable Roadmap

Specific, prioritized learning steps tailored to identified gaps and target role. Numbered list format for clear follow-through.

🎯

Recruiter Follow-Up Qs

AI-generated targeted questions for the next interview round — with rationale, target skill, uncertainty level. Ordered by uncertainty (most uncertain first).

📈

Consistency Analysis

Statistical std-deviation analysis of scores across all answers: High / Moderate / Low / Variable. Shows how consistent performance was throughout the session.

🛡️

Integrity Status Panel

Verified Clean ✅ / Warning Issued ⚠️ / Terminated ❌ with full audit trail: timestamps, question context at each event, policy version.

📋

Copy & Export

One-click copy of evidence citations and recruiter follow-up questions to clipboard. Clipboard API with textarea fallback for older browsers.

Section 05

AI Assistant Panel

A collapsible real-time AI chat widget embedded in two places: the live interview workspace, and the candidate dashboard's Practice tab.

In Interview Mode

  • Context-aware of the current question topic and category
  • Knows the candidate's target role & experience level
  • Provides conceptual clarifications without giving away answer content
  • Access-controlled: Returns 403 if session terminated for integrity violation — chat UI locks with explanation
  • Maintains rolling last-6-message history for contextual, coherent responses
  • Error state shown on API failure — retry button available

In Practice Mode (Dashboard)

  • Open-ended chat for general interview preparation
  • Answers questions on concepts, coding patterns, system design best practices
  • No session restrictions — freely available any time from dashboard
  • Auto-scrolls to latest messages
  • Keyboard shortcut: Enter to send, Shift+Enter for newline
  • Fully collapsible panel to save screen space

🔐 Security: The /api/ai-assistant/chat route checks the session's integrity status on every request in interview mode. Terminated sessions receive a hard 403 response regardless of what the client sends. Session ID validated server-side on each message.

Section 06

API Reference (20+ Routes)

All routes are Next.js Route Handlers in frontend/src/app/api/. They run exclusively server-side — never bundled to the browser. Every route that needs auth calls resolveRequestUser(req).

🔐 Authentication Routes

POST/api/auth/loginVerify email+password, create session, set HTTP-only cookie (7-day expiry)
POST/api/auth/registerCreate new user account. Role (candidate/recruiter) set at signup.
GET/api/auth/meGet authenticated user from session cookie. Returns user object or {authenticated:false}.
POST/api/auth/logoutDelete session from DB, clear cookie. Idempotent (safe to call multiple times).
POST/api/auth/demo-login1-click demo account login. Body: {email}. No password in URL. Returns session cookie.

🎤 Interview Session Routes

GET/api/interview/session?id={sessionId}Fetch saved session from DB including integrity events and answer count.
POST/api/interview/sessionCreate or upsert interview session record. Validates userId from server session, not body.
POST/api/interview/answerPersist a candidate answer turn with full feedback JSON to DB.

🤖 AI-Powered Interview Routes

POST/api/interview/generate-questionGenerate first question via Gemini AI using setup config + resume context + asked-question dedup list.
POST/api/interview/evaluate-answerEvaluate candidate answer. Returns full AnswerFeedback: score, strengths, gaps, evidence quote, labels.
POST/api/interview/next-questionAdaptive next question based on last answer, keyword triggers, full session history. Branching logic applied server-side.
POST/api/interview/generate-reportFull AI evaluation report: score, verdict, skill metrics, evidence citations, recruiter follow-ups, roadmap.

📊 Report Routes

GET/api/interview/report/[sessionId]Fetch evaluation report. Candidate: own session only. Recruiter: any session. 403 on ownership mismatch.
GET/api/interview/reportsList all reports. Role-scoped: candidates get own only, recruiters get all across platform.

🛡️ Integrity Routes

POST/api/interview/integrity/eventRecord focus-loss violation. Server computes count and decides: warning (1st) or termination (2nd). Idempotency checked.
POST/api/interview/integrity/ack-policyRecord candidate policy acknowledgment with authoritative server timestamp + policy version (v1.0).
GET/api/interview/integrity/auditFull integrity event audit log for a session (all events, action taken, timestamps, question context).

💼 Recruiter Routes

POST/api/interview/reviewSubmit shortlist status + notes. Requires recruiter role — candidates receive 403 Forbidden.
GET/api/interview/reviewsGet all recruiter review records with candidate info. Recruiter-only.

💬 AI Assistant Route

POST/api/ai-assistant/chatContextual chat. Interview mode: session-aware with integrity check. Practice mode: free-form. Rolling 6-message history.

Section 08

Security Architecture

🔐

Server-Side Auth Verification

Every API route calls resolveRequestUser(req). Client-supplied user IDs in JSON bodies are NEVER trusted — always overridden by server-session user.

🧂

Password Security

PBKDF2-SHA512 with 100,000 iterations, unique 16-byte random salt per user. crypto.timingSafeEqual() prevents timing-attack exploitation during login.

🍪

HTTP-Only Cookies

Session tokens inaccessible to JavaScript. 32-byte cryptographic random hex. 7-day expiry checked in DB on every request.

🚦

Role-Based Access Control

Recruiter-only endpoints return 403 for candidates. Session ownership verified before ANY write to sessions or reports. Cross-user access returns 403.

💉

Prompt Injection Defense

Resume XML-bounded: <candidate_resume_untrusted_data>. Control chars stripped. Gemini explicitly instructed to ignore embedded commands.

🔒

Cross-Session Isolation

Before question gen, answer recording, report creation — API verifies session.userId === authenticatedUser.id. Mismatch returns 403.

🛡️

Server-Side Integrity Counts

Violation counts computed exclusively server-side. Any client-supplied violationCount, actionTaken, or status in request bodies are silently rejected.

🔄

Idempotency Protection

Integrity events carry unique idempotency keys. Duplicate submissions (from network retries) detected and deduplicated in DB. Same violation can never count twice.

Data Trust Boundaries

Data FieldTrusted?Handling Strategy
Session cookie token✅ VerifiedLooked up in DB, expiry checked server-side on every request
Client-supplied userId in body❌ NeverAlways overridden by server-authenticated session user ID
Resume text from upload⚠️ UntrustedSanitized, bounded to 1500 chars, XML-wrapped, prompt injection instructions
Client-supplied violationCount❌ NeverExplicitly rejected; count computed server-side from DB events
Session status in request body❌ NeverAlways read from DB — client-provided status fields ignored
Candidate answer text⚠️ BoundedStored verbatim but evaluated in isolated Gemini context; not executed

Key Design Decisions

  • Dark Mode Only: Entire UI uses deep navy (#090e1a) dark theme — no light/dark toggle needed
  • No External Auth Libraries: Custom PBKDF2 auth without NextAuth, Clerk, Auth0, or similar dependencies
  • No Client-Side DB Queries: All Prisma queries run exclusively in API route handlers (server-side only)
  • Dual Persistence Strategy: Session + answers saved to both localStorage (fast UX) and SQLite (authoritative source of truth)
  • Graceful AI Degradation: Static question bank as fallback ensures 100% availability even when Gemini is unreachable
  • TypeScript End-to-End: Fully typed across frontend UI, API routes, DB layer (lib/types.ts), and AI client
  • Zero Client Trust: API routes never trust client-supplied userId, violationCount, session status, or user role claims
  • Monorepo + npm Workspaces: Single root package.json with workspace scripts for concurrent dev of both services
  • Next.js 16 Middleware Naming: Uses proxy.ts instead of the old middleware.ts name (Next.js 16 breaking change)
